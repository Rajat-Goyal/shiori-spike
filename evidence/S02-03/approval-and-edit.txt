creation tool interrupt the active durable run. The application renders the
preview and seals the paused state against the exact tool, owner chat, session,
entity ID, and version. Unit tests prove the consequential callback is not
invoked before approval.

AC2 PASS — Creation continues to resume the same encrypted interrupted run and
uses the existing atomic confirmation transaction. Approval tests preserve the
exact creation binding and reject stale, mismatched, replayed, or rejected
interactions without a second consequence.

version 2, cancels the obsolete unsent reminder, creates the version-2

work-shaped probe cancels the former planned session and both unsent messages,

AC4 PASS — ApprovedCommitmentChangeService rechecks the exact proposed window
immediately before the transaction. Unit tests cover free, reject-on-conflict,
explicit conflict keep, reject-on-unavailable, and explicit unverified-save
policies. Calendar is read-only and raw Calendar data is not persisted.

AC5 PASS — Runtime, approval-gate, callback, service, and local database tests
cover rejection, authority mismatch, stale versions, exact replay, terminal
commitments, and interrupted retry. The transaction probe proves exact replay
is harmless, a different stale update cannot mutate, and a completed promise
cannot reopen.

Database and security notes
- The edit RPC owns one row-locked transaction for commitment fields, planned
  work-session replacement, unsent schedule cancellation/replacement, receipt,
  version increment, and append-only change event.
- Existing target immutability remains fail-closed. Only the approved edit RPC
  sets a transaction-local binding for the exact commitment while performing
  its version-checked update.
- Change-event metadata contains only changed field names and versions.
- No production or remote Supabase state was accessed or changed.
- Local Supabase credentials were supplied only to the test process and are
  not present in this artifact.
